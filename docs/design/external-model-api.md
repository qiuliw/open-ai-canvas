# 对外模型 API 与 API Key 管理

本次按当前任务实现多 Key，取代旧分支未实施的全站单 Key 草案。

## 设计

- 复用 Go/Gin 后端、GORM 数据库、CreateTask 准入、计费与 Worker 协议插件。独立代理服务会重复权限和计费逻辑，直接开放渠道中转则权限过宽，因此采用现有任务入口。
- 登录账号通过 `/api/api-keys` 签发、列出、吊销自己的 Key；Key 不能管理 Key，也不能成为站内登录凭证。
- 32 字节密码学随机密钥以 `yc_` 开头，仅创建时返回。数据库保存 SHA-256、可显示前缀、归属、名称、到期和吊销时间。每次鉴权查询数据库并检查账号状态，无缓存。
- Bearer Key 访问 `/api/model-calls/models`、`/api/model-calls` 和 `/api/model-calls/:id`。调用按 Key 所属账号的模型目录、额度和积分执行。查询仅允许该 Key 创建的任务。
- 请求支持模型标识 `channelId::modelKey`、能力（默认 text）、文本消息和明确类型的生成参数。只允许系统渠道，拒绝自带凭证、地址和任意任务上下文。首版不接收工具调用、参考媒体或 SSE。
- 所有能力异步返回任务 ID，调用方查询结果；避免 HTTP 长连接与反向代理超时。结果只投影公开字段，不暴露渠道配置、上游任务 ID、原始错误或内部任务输入。
- 数据库版本升级新增 API Key 表和服务端专用 `tasks.api_key_id`。Key 归属随任务和账单原子保存，避免孤立任务或客户端伪造归属。

## 实施与验收

1. Key 生命周期、散列持久化、到期、禁用用户和归属隔离的测试先行。
2. 对外模型调用转换、参数验证、请求大小、独立鉴权和跨 Key 查询隔离测试先行；通过真实 Worker 与本地假上游验证模型执行。
3. 补 OpenAPI、中文 curl 文档、数据库和代码地图；运行后端测试、竞态专项和构建。

不修改现有工作区的未提交文档，不推送或部署，不使用真实上游密钥。
